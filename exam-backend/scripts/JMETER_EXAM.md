# 完整考试流程与集中交卷压测

从 `exam-backend` 目录执行。需要本机 MySQL、Redis、正常运行的后端（8077）、JDK 21、JMeter 5.6.3，以及 `scripts/jmeter_accounts.csv` 中至少 1000 个不同的有效测试账户。数据库连接读取项目 `.env`，不要把密码或登录令牌放进报告。

```powershell
# 如后端尚未运行，可使用已有启动脚本
powershell -ExecutionPolicy Bypass -File scripts/start_loadtest_backend.ps1

# 1000 个账户，20 秒内启动，持续 20 轮、每轮间隔 30 秒自动保存，然后集中交卷
python scripts/run_jmeter_exam.py --users 1000 --ramp 20 --cycles 20 --save-interval 30

# 将上述命令输出的结果目录替换到这里，生成报告和资源图
python scripts/report_exam_loadtest.py scripts/load-test-results/exam-实际时间戳

# 单独验证重复交卷与保存交卷竞态；不要与主测试同时运行
python scripts/probe_exam_submit_races.py --users 20

# 跨试卷共享错题并发累计、重考、超时草稿判分回归；同样单独运行
python scripts/probe_wrong_question_upsert.py
```

测试会写入数据库。每次运行新建独立科目、50 道客观题和试卷，结束后关闭本轮试卷入口，保留试卷、答案和成绩供核对。不会清空原有考试记录。不要在生产数据库执行；本脚本用于当前本机测试环境。

## 测试内容

每个账户依次完成登录、查询试卷、读取题目、开考、读取空草稿、保存部分答案、恢复草稿、刷新续考、逐步答题并定时保存、恢复完整答案、集中交卷、查看成绩与答题明细、重复交卷拦截、交卷后保存拦截、查询考试记录和错题本。

题目为 20 道单选、20 道多选、10 道判断，每题 2 分。每人固定答错 10 题，预期 80 分。不同账户的错误题目按用户编号分配，避免只验证同一份答案。每轮自动保存传递全部 50 道题的当前答案，与前端的 30 秒保存间隔对应。

集中交卷前使用 JMeter 同步定时器等待全部测试用户，等待上限 180 秒。报告记录实际请求发起跨度；如果有人未到达，覆盖检查会失败。HTTP 自动重试关闭。除 HTTP 状态外，脚本还检查业务响应和数据内容，因此返回 HTTP 200 的业务错误也会被识别。

默认主测试共有 35000 次正式请求，另有 10 次预热登录。正式请求包含 20000 次自动保存和 1000 次集中交卷，其中重复交卷、交卷后保存共 2000 次应被业务规则拒绝；只有返回指定拒绝原因才算通过。

测试结束后直接核对数据库：1000 份已交卷记录、50000 条答题明细、10000 条错题；逐人核对答案、判分、成绩、最高分、考试次数和错题次数。请求遗漏或数据不一致都会导致运行失败。

独立竞态探针让每个账户的两次交卷和一次空答案保存同时竞争，检查每人恰好一次交卷成功、另一次被拒绝，最终答案不被覆盖，错题不被重复累计。

## 结果与限制

每轮结果位于 `scripts/load-test-results/exam-时间戳/`：

- `report.md`、`resources.png`：可读报告及资源变化图（运行报告生成命令后产生）。
- `summary.json`：各阶段延迟、错误、请求覆盖和独立数据库核对结果。
- `results.jtl`：逐条请求数据，包含测试账户、用户和考试记录编号，不记录密码或令牌。
- `resources.jsonl`：每秒采样的 CPU、内存与 MySQL 状态。
- `exam-flow.jmx`：本轮实际执行的 JMeter 计划。
- `fixture.json`：本轮合成试卷及预期答案。

这是接口级测试。1000 名活跃考生每 30 秒自动保存，并不等于始终有 1000 个 HTTP 请求同时执行；集中交卷单独通过同步屏障制造峰值。测试使用可信设备登录和客观题，不覆盖邮件验证、浏览器渲染、教师人工批改或远程网络。压测工具、后端和数据库在同一台机器，结论只适用于本轮配置与负载，不能直接当作生产容量上限。

不要同时运行多轮测试：它们使用同一批账户，重复登录可能影响登录状态，也会混淆资源统计。

## 交卷优化的配置与回归

JDBC 连接已启用 `rewriteBatchedStatements=true`。错题保存通过一次批量查询区分新增与已有记录，分别批量插入、按主键批量更新并在 SQL 内累加错误次数。同一用户的考试写操作按“用户行 → 考试记录行 → 答案和错题”顺序加锁，避免共享错题的并发累计丢失。50 题场景仍在同一事务内完成交卷，任一失败会回滚，HTTP 不自动重试。

`DatabaseMigrationRunner` 启动时添加 `wrong_question(user_id, question_id)` 唯一索引。已检查当前本机数据没有重复组合。其他环境如有历史重复数据，新增唯一索引会失败，需先核对处理；迁移不会自动删除或合并历史记录。启动日志中的索引迁移失败必须解决后再使用优化版本。

连接池最大值保持 50；认证仍实时读取账户状态并检查 Redis 登录版本，仅复用已验证的 JWT Claims，将成功鉴权日志降为 DEBUG。没有引入延迟生效的权限缓存。

新增错题回归会创建三张独立试卷，20 个账户的两场考试使用相同题目并同时交卷，检查同一道错题只保留一条记录、次数累计到 2；重考后累计到 3；超时草稿判分后累计到 4。还检查错题主键和创建时间不被替换、掌握状态正确重置。这个回归覆盖了原来单张试卷压测未覆盖的共享错题更新分支。
